# 数据字典

## 维护说明

- MongoDB 和 Milvus 都不适合直接承载长期字段备注：Mongo 没有稳定的集合/字段注释机制，Milvus 的 schema description 更偏运行时结构说明。
- 本文档作为项目级数据字典，解释 Mongo 集合、Milvus collection 和关键字段含义。
- 后续 schema、字段含义或阶段状态发生变化时，应同步更新本文档。
- 字段状态说明：
  - `已落地`：当前代码或数据库记录中已经使用。
  - `阶段 4 计划`：阶段 4 方案中计划新增或调整，尚未全部落地。
  - `预留`：为后续权限、多租户、管理能力预留。

## Mongo 元数据

Mongo 元数据数据库：`ai_mfg_kb_meta`

当前主要集合：

| 集合 | 状态 | 含义 | 备注 |
|---|---|---|---|
| `datasets` | 已落地 | 知识库容器集合 | 当前默认知识库为设备运维知识库。 |
| `documents` | 已落地 | 文档元数据集合 | 记录上传文件、解析状态、索引状态、用户归属和失败信息。 |
| `tasks` | 已落地 | 导入任务集合 | 记录导入、后续重建等任务进度和失败信息。 |
| `chat_message` | 已落地 | 聊天历史集合 | 保存用户/助手消息；助手消息同时保存 Citation、Trace ID 和终止原因码。 |
| `retrieval_traces` | 已落地 | 单次查询检索轨迹集合 | 增量保存 Planner/Action/Observation、配置快照、用量、候选摘要和最终引用；不保存 chunk 正文。 |

### datasets

一条记录表示一个知识库容器。

| 字段 | 类型/形态 | 状态 | 含义 | 备注 |
|---|---|---|---|---|
| `_id` | ObjectId | 已落地 | Mongo 内部主键 | 不作为业务关联字段。 |
| `dataset_id` | string | 已落地 | 知识库业务 ID | 当前默认值为 `dataset_default_equipment_ops`。 |
| `name` | string | 已落地 | 知识库名称 | 当前默认名称为“设备运维知识库”。 |
| `description` | string | 已落地 | 知识库说明 | 用于展示和排查。 |
| `created_at` | ISO datetime string | 已落地 | 创建时间 | UTC ISO 字符串。 |
| `updated_at` | ISO datetime string | 已落地 | 更新时间 | 每次默认 dataset 确认时会更新。 |

### documents

一条记录表示一个上传后的文档对象。文档是长期对象，task 是一次执行记录。

| 字段 | 类型/形态 | 状态 | 含义 | 备注 |
|---|---|---|---|---|
| `_id` | ObjectId | 已落地 | Mongo 内部主键 | 不作为业务关联字段。 |
| `document_id` | string | 已落地 | 文档业务 ID | document 的稳定标识，chunk 已关联该字段。 |
| `dataset_id` | string | 已落地 | 所属知识库 ID | 关联 `datasets.dataset_id`。 |
| `owner_user_id` | string | 已落地 | 文档所属用户 | 阶段 3.5 引入，用于导入历史隔离。 |
| `tenant_id` | string | 预留 | 租户 ID | 当前默认 `tenant_default`，后续多租户使用。 |
| `visibility` | string | 预留 | 可见性 | 当前默认 `private`，后续支持 `private/shared/public`。 |
| `latest_task_id` | string | 已落地 | 最新任务 ID | 指向该 document 最近一次导入或重建任务。 |
| `file_name` | string | 已落地 | 原始文件名 | 上传时的文件名。 |
| `file_path` | string | 已落地 | 原始文件本地路径 | 后续重建索引可复用。 |
| `local_dir` | string | 已落地 | 当前导入或重建任务工作目录 | 保存解析产物和中间文件；重建时更新为新 task 的工作目录。 |
| `status` | string | 已落地 | 文档整体状态 | 常见值：`uploaded`、`processing`、`completed`、`failed`、`deleted`。 |
| `parse_status` | string | 已落地 | 解析阶段状态 | 表达文件检查、PDF 转 Markdown、图片增强等解析链路状态。 |
| `index_status` | string | 已落地 | 索引阶段状态 | Milvus 插入成功后写 `completed`；异常由导入失败收口写 `failed`。 |
| `chunk_count` | int | 已落地 | 当前文档切片数量 | 切分时写入预期数量，Milvus 插入成功后按实际入库 chunks 再次确认。 |
| `subject_id` | string | 已落地 | 标准主题 ID | 关联 Milvus 标准主题和 chunk；Milvus 插入成功后随最终索引结果确认。 |
| `standard_subject_name` | string | 已落地 | 标准主题名称 | 用于展示、日志和答案 Prompt；Milvus 插入成功后随最终索引结果确认。 |
| `md_path` | string | 已落地 | 最终 Markdown 路径 | PDF 解析或 Markdown 图片增强后写入。 |
| `file_title` | string | 已落地 | 文件标题 | 通常来自文件名 stem，用于展示和主体识别兜底。 |
| `failed_node` | string | 已落地 | 失败节点 | 记录失败发生在哪个导入节点。 |
| `error_message` | string | 已落地 | 失败信息 | 面向排查的技术错误信息。 |
| `created_at` | ISO datetime string | 已落地 | 创建时间 | UTC ISO 字符串。 |
| `updated_at` | ISO datetime string | 已落地 | 更新时间 | 元数据状态变化时更新。 |
| `index_version` | int | 已落地 | 文档级检索索引产物版本 | 表示该 document 生成到第几版 chunk/vector 入库结果；Milvus 插入成功后随最终索引结果确认，不是 Milvus 物理索引版本或文档内容版本。 |
| `deleted_at` | ISO datetime string | 已落地 | 删除时间 | 文档软删除成功时写入；为空表示未删除。 |
| `image_prefix` | string | 已落地 | 图片对象前缀 | 图片增强有可处理图片时写入 document 维度前缀，例如 `kb-images/{document_id}`；删除 document 时按该精确前缀清理。 |
| `parse_result_zip_path` | string | 已落地 | MinerU 解析结果 zip 路径 | PDF 解析完成后写入本地 zip 路径；Markdown 直接导入时为空。 |
| `parse_result_dir` | string | 已落地 | MinerU 解析结果解压目录 | PDF 解析完成后写入本地解压目录；Markdown 直接导入时为空。 |

| 字段 | 类型/形态 | 状态 | 含义 | 备注 |
|---|---|---|---|---|

| `task_id` | string | 已落地 | 任务业务 ID | 一次执行的稳定标识。 |
| `document_id` | string | 已落地 | 关联文档 ID | 关联 `documents.document_id`。 |
| `dataset_id` | string | 已落地 | 所属知识库 ID | 关联 `datasets.dataset_id`。 |

| `task_type` | string | 已落地 | 任务类型 | 支持普通导入 `import` 和重建索引 `rebuild_index`。 |
| `status` | string | 已落地 | 任务状态 | 常见值：`pending`、`processing`、`completed`、`failed`。 |
| `running_nodes` | list[string] | 已落地 | 正在运行的节点列表 | 保存节点原始名称，API 返回时会映射中文展示名。 |
| `done_nodes` | list[string] | 已落地 | 已完成的节点列表 | 保存节点原始名称。 |
| `failed_node` | string | 已落地 | 失败节点 | 导入失败时记录最后运行节点或明确失败节点。 |

| `completed_at` | ISO datetime string | 已落地 | 完成时间 | 任务完成时写入。 |
| `failed_at` | ISO datetime string | 已落地 | 失败时间 | 任务失败时写入。 |
| `task_type=rebuild_index` | enum value | 已落地 | 重建索引任务类型 | 任务类型枚举值，持久记录；运行进度仍由 `status` 表达。 |

### retrieval_traces

一条记录表示一次查询执行的可重放检索轨迹。`trace_id` 是单次执行 ID，`session_id` 是聊天会话 ID；一个会话可以包含多条 Trace。

| 字段 | 类型/形态 | 状态 | 含义 | 生命周期与边界 |
|---|---|---|---|---|
| `trace_id` | string | 已落地 | 单次查询全局唯一 ID | 查询入口生成；Mongo 唯一索引；不等于 `session_id`。 |
| `session_id` | string | 已落地 | 所属聊天会话 | 用于同一会话内多次查询回溯。 |
| `owner_user_id` / `tenant_id` / `dataset_ids` | string/string/list[string] | 已落地 | 用户、租户和知识库范围快照 | 从查询入口写入；后续 Trace 查询仍必须按 owner 隔离。 |
| `original_query` / `rewritten_query` | string | 已落地 | 原始问题与主体确认后的检索问题 | 可保存用户问题，但不保存答案 Prompt 和模型私有思维链。 |
| `subject_ids` / `standard_subject_names` | list[string] | 已落地 | 已确认主题身份 | 从主体确认结果投影。 |
| `query_identifiers` / `identifier_resolution_status` / `suggested_identifiers` | object/enum/object | 已落地 | 用户编号、编号确认状态和待确认候选 | 不同编号只能作建议，不得进入最终 Citation。 |
| `policy_version` / `planner_type` | string | 已落地 | Planner 策略版本与类型 | 当前为 `rule-v1` / `rule`；用于稳定重放和策略对比。 |
| `provider` / `model_id` / `model_revision` / `prompt_version` | nullable string | 已落地 | Planner 模型身份 | 规则 Planner 为 null；未来 Model Planner 记录真实值。 |
| `planner_usage` / `answer_usage` | `UsageMetrics` | 已落地 | Planner/答案模型 token、耗时和费用 | provider 未返回 token 或未配置计价时记 0，不伪造精确值。 |
| `retrieval_config_version` | string | 已落地 | 检索配置版本名 | 用于快速分组；不能代替完整快照。 |
| `retrieval_config_snapshot` | `RetrievalConfigSnapshot` | 已落地 | 本次真正生效的检索超参 | 保存 mode、每路 top-k、融合 top-k、rerank 范围、RRF k、证据阈值和 Web fallback。 |
| `planner_steps` | list[`TracePlannerStep`] | 已落地 | 按顺序保存的 Decision/Action/Observation | Planner 决定后先增量写 pending，Action 完成后覆盖同一 step 为 completed/failed。 |
| `channel_hits` | list[`TraceChannelHit`] | 已落地 | 各已执行检索 Action 的候选摘要 | 只保存 ID、排名、分数、编号和 SHA-256；不保存 chunk 正文。 |
| `final_citations` | list[`Citation`] | 已落地 | 真正进入最终答案上下文的引用 | 追问、拒答和答案模型失败时为空。 |
| `status` / `terminal_action` / `terminal_reason_code` | enum | 已落地 | Trace 状态和最终决策 | `running` 在入口创建；正常终止写 `completed`；未收口异常写 `failed`。 |
| `started_at` / `completed_at` / `total_duration_ms` | string/string/int | 已落地 | 开始、结束与总墙钟耗时 | 时间使用 UTC ISO 8601；耗时单位毫秒。 |
| `error_code` | nullable string | 已落地 | 未处理异常的机器错误码 | 不保存异常堆栈、连接密钥或候选正文。 |

`retrieval_traces` 在模块 import 时不连接 Mongo，只在真实 HTTP 查询开启 `trace_persistence_enabled` 后懒加载仓储。Trace 写入失败会记录日志，不应遮蔽本来可正常交付的答案。

## 导入图运行时状态

`ImportGraphState` 是一次导入图执行期间的运行时状态，不是长期存储表。节点只返回 partial state，长期可追踪字段由节点通过 repository 回写到 Mongo `documents`。

### ImportGraphState 解析产物字段

| 字段 | 类型/形态 | 状态 | 写入节点/服务 | 含义 | Mongo 落点 |
|---|---|---|---|---|---|
| `md_path` | string | 已落地 | `node_pdf_to_md` / `node_md_img` | 最终进入切分流程的 Markdown 文件路径。 | `documents.md_path` |
| `md_content` | string | 已落地 | `node_pdf_to_md` / `node_md_img` | Markdown 完整正文内容，后续切分基于该字段或 `md_path` 读取。 | 不长期保存全文 |
| `parse_result_zip_path` | string | 已落地 | `parse_pdf_to_markdown` | MinerU 解析结果 zip 本地路径，仅 PDF 导入时写入。 | `documents.parse_result_zip_path` |
| `parse_result_dir` | string | 已落地 | `parse_pdf_to_markdown` | MinerU 解析结果解压目录，仅 PDF 导入时写入。 | `documents.parse_result_dir` |
| `image_prefix` | string | 已落地 | `enrich_markdown_images` | 当前 document 在 MinIO 中的图片对象前缀，有可处理图片时写入。 | `documents.image_prefix` |

| state 字段 | 类型/形态 | 状态 | Milvus 落点 | 含义 |
|---|---|---|---|---|
| `dataset_id` | string | 已落地 | `CHUNKS_COLLECTION.dataset_id` | 当前导入目标知识库 ID。 |
| `document_id` | string | 已落地 | `CHUNKS_COLLECTION.document_id` | 当前导入 document ID，也是 chunk 幂等删除业务键。 |
| `owner_user_id` | string | 已落地 | `CHUNKS_COLLECTION.owner_user_id` | 当前 document 所属用户 ID。 |
| `tenant_id` | string | 已落地 | `CHUNKS_COLLECTION.tenant_id` | 当前租户 ID；为空时入库默认 `tenant_default`。 |
| `visibility` | string | 已落地 | `CHUNKS_COLLECTION.visibility` | 当前 document 可见性；为空时入库默认 `private`。 |
| `index_version` | int | 已落地 | `CHUNKS_COLLECTION.index_version` | 当前 document 检索索引产物版本。 |
| `file_title` | string | 已落地 | `CHUNKS_COLLECTION.source_title` | 当前来源标题；同时保留 `file_title` 作为展示兼容字段。 |

## 查询图运行时状态

`QueryGraphState` 是一次查询进入 LangGraph 后的运行时状态，不是 Mongo 持久化记录。阶段 5 第三部分补齐 Planner/Observation/引用字段，第四部分统一权限 filter，第五部分接入设备标识与编号 Observation，第六部分统一 original、HyDE、Web 的候选契约、两层 RRF 和 rerank 元数据，第七部分补齐 chunk 的 learned sparse/BM25 实验 schema，第八部分实现确定性 RuleBasedPlanner，第九部分接入真实查询图，第十至十二部分已经完成 Mongo Retrieval Trace、结构化 Citation 输出和配置快照持久化。

### QueryGraphState 查询上下文字段

| state 字段 | 类型/默认值 | 来源/写入方 | 含义与边界 |
|---|---|---|---|
| `session_id` | string / `""` | `/query` 请求体 | 聊天会话 ID，用于历史、SSE 和任务进度；不能代替用户身份，也不等于单次执行 Trace。 |
| `original_query` | string / `""` | `/query.query` | 用户未经改写的原始问题，后续节点不得覆盖。 |
| `is_stream` | bool / `false` | `/query.is_stream` | 是否通过 SSE 增量交付答案；不应改变检索范围和 Planner 决策。 |
| `owner_user_id` | string / `""` | `/query` 的 `X-User-Id` 请求头 | 当前轻量用户 ID。缺失或只有空白字符时 HTTP 层返回 400，请求不会进入 LangGraph。 |
| `tenant_id` | string / `""` | 查询 API 默认配置 | 真实查询当前写入 `tenant_default`；仅表示轻量单租户上下文，不代表已完成完整租户鉴权。 |
| `dataset_ids` | list[string] / `[]` | `QueryRequestParam.dataset_ids` | 本次查询目标知识库范围。省略时使用默认设备运维知识库；显式空列表拒绝，去空、保序去重后最多 10 个。 |
| `query_started_at` | string / `""` | 查询图入口 | 单次查询开始时间；真实请求写入带 UTC 时区的 ISO 8601 时间，用于耗时计算和 Trace 排序。 |
| `rewritten_query` | string / `""` | 主体确认节点 | 结合历史改写后的独立问题；不能反向覆盖 `original_query`。 |
| `subject_ids` | list[string] / `[]` | 主体确认节点 | 已确认标准主题的稳定业务 ID；后续本地检索按它过滤。 |
| `standard_subject_names` | list[string] / `[]` | 主体确认节点 | 标准主题展示名，用于日志和 Prompt，不作为稳定关联主键。 |
| `subject_resolution_status` | `SubjectResolutionStatus \| None` / `None` | 主体确认节点 | 主体确认结果枚举。`None` 只表示节点尚未执行；完成后必须为 `confirmed/ambiguous/not_found/no_mention` 之一。 |
| `subject_candidates` | list[string] / `[]` | 主体确认节点 | 主体存在歧义时可供用户选择的候选名称；不会直接写入最终 answer。 |
| `clarification_question` | `string \| None` / `None` | 主体规则/普通检索编号规则 | 可直接返回给用户的确定性追问文本，不保存模型私有思维链；第五部分在 `suggestion_required/not_found` 时写入。 |
| `query_identifiers` | dict[string, list[string]] / `{}` | 查询图入口；旧调用缺字段时普通检索兜底 | 用户原问题中实际出现并归一化的设备型号、报警码、SOP/零件编号等标识。空字典也是“已提取但未发现编号”的有效结果，不能再从改写问题猜测；纠错候选属于 Observation 的 `suggested_identifiers`。 |
| `history` | list[dict] / `[]` | 主体确认服务 | 当前会话历史的运行时副本；完整 `user_id + session_id` 隔离仍属于阶段 7。 |

### Planner、Observation 与输出字段

| state 字段 | 类型/默认值 | 来源/写入方 | 含义与边界 |
|---|---|---|---|
| `trace_id` | string / `""` | 查询图入口 | Trace 即“单次执行追踪”。真实请求每次生成独立 UUID；同一 `session_id` 的多次查询不能复用。 |
| `planner_step` | int / `0` | Observation/Trace 收口节点 | 已经实际执行完的 Action 数；与 history 长度一致，用于轨迹排序和最大步数保护。未执行的 Decision 不增加。 |
| `policy_version` | string / `""` | Planner 节点 | 规则策略执行后写 `rule-v1`；后续规则顺序或语义变化必须升级。 |
| `current_planner_decision` | `PlannerDecision \| None` / `None` | Planner 节点 | 最近一次已通过 Pydantic 校验的 Action、query 和 reason code；路由只读取其中的 action。 |

### 统一 Milvus 查询过滤契约

| 函数 | 状态 | 输入 | 输出与边界 |
|---|---|---|---|
| `build_chunk_access_filter` | 已落地 | `dataset_ids`、`owner_user_id`、`tenant_id` | 输出 dataset、`enabled == true` 和 public/shared/owner 可见性条件；三个 OR 分支始终使用完整括号。 |
| `build_structured_identifier_filter` | 已落地 | `query_identifiers` | 可选输出设备运维精确字段条件；未知 schema 字段和显式空值拒绝，不把字典 key 直接拼入 expr。 |
| `select_structured_query_identifiers` | 已落地 | 完整查询标识字典 | 只选择当前 Milvus schema 可映射字段；允许 `sop_code/part_number` 留在 State 和检索文本，但不伪造字段条件。 |
| `build_chunk_retrieval_filter` | 已落地 | access 输入、`subject_ids`、可选标识 | 合并为所有本地召回通道使用的最终 expr；dataset/subject 为空时禁止全库搜索。 |
| `build_chunk_retrieval_filter_from_state` | 已落地 | `QueryGraphState` | 普通检索、HyDE 读取过滤上下文的唯一适配入口；不回退匿名用户或默认范围。 |

可见性规则：

```text
dataset_id in 当前 dataset_ids
AND subject_id in 已确认 subject_ids
AND enabled == true
AND (
    visibility == "public"
    OR (visibility == "shared" AND tenant_id == 当前 tenant_id)
    OR owner_user_id == 当前 owner_user_id
)
```

动态字符串统一去除首尾空白、保序去重并进行 Milvus 引号/反斜杠/换行转义。当前结构化标识白名单只包含 chunk schema 已存在的 `equipment_model`、`alarm_code`、`part_name`、`sop_type`、`safety_level`、`maintenance_stage`。第五部分已经自动提取 `equipment_model`、`alarm_code`、`sop_code` 和带明确上下文的 `part_number`；其中后两者当前只进入增强检索文本，不进入 Milvus 字段表达式。

普通检索、HyDE 以及同一次 hybrid search 内的所有请求共享同一 expr。第六部分已能按 `RetrievalMode` 创建 dense/learned sparse/BM25 请求，并让 chunk collection 使用 `RRFRanker(k=60)`；第七部分已补齐 `learned_sparse_vector`、`lexical_text`、`bm25_sparse_vector` 和 BM25 Function。默认仍是 dense + learned sparse；BM25 和三路模式用于固定评测，不代表已经选定线上最终组合。

两段式检索的第二段只允许移除结构化标识条件，不能移除权限、dataset、subject 或 `enabled`。宽松召回后如果正文仍命中用户原编号，可标记 `fallback_exact_match` 并继续作为证据；如果只找到不同编号，必须标记 `suggestion_required`、写入 `suggested_identifiers` 并追问用户，不能进入答案 Citation。

### CHUNKS_COLLECTION

知识切片集合，一条 chunk 一条记录，存储问答检索用的正文、元数据和混合检索向量。

阶段 4 已将 chunk 从文件标题维度升级到 document 维度。当前不做旧 schema 在线兼容；本地或测试 Milvus 集合如果仍是旧字段结构，可以删除集合后由导入流程重建。

| 字段 | 类型/形态 | 状态 | 含义 | 备注 |
|---|---|---|---|---|
| `chunk_id` | INT64 auto_id primary key | 已落地 | Milvus 自动生成的 chunk 主键 | 用于返回检索命中的切片标识，不作为业务幂等键。 |
| `content` | VARCHAR | 已落地 | 切片正文内容 | 答案生成阶段主要依据该字段组织回答。 |
| `file_title` | VARCHAR | 已落地 | 来源文件标题 | 仅作为展示和兼容字段，不再作为导入幂等删除条件。 |
| `title` | VARCHAR | 已落地 | 当前切片标题 | 通常来自 Markdown 标题。 |
| `parent_title` | VARCHAR | 已落地 | 父级标题 | 保留章节层级，帮助定位切片上下文。 |
| `part` | INT8 | 已落地 | 分片顺序标记 | 表示该 chunk 在章节拆分结果中的顺序。 |
| `subject_id` | VARCHAR | 已落地 | 标准主题 ID | 阶段 2 后查询优先用该字段过滤 chunk。 |
| `standard_subject_name` | VARCHAR | 已落地 | 标准主题名称 | 可读展示字段，检索过滤不依赖该字段。 |
| `equipment_model` | VARCHAR | 已落地 | 设备型号 | 已进入结构化 filter 白名单；查询入口把 `HAK180/HAK-180/HAK 180` 统一为 `HAK 180` 后精确过滤。 |
| `alarm_code` | VARCHAR | 已落地 | 报警码或故障码 | 已进入结构化 filter 白名单；查询入口独立提取 E020/E021，禁止用向量相似度自动互相纠正。 |
| `part_name` | VARCHAR | 已落地 | 部件名称 | 已进入结构化 filter 白名单；当前查询尚未自动提取。 |
| `sop_type` | VARCHAR | 已落地 | SOP 类型 | 已进入结构化 filter 白名单；字段表达 SOP 类型，不等同于尚未定义的 SOP 编号。 |
| `safety_level` | VARCHAR | 已落地 | 安全等级或风险级别 | 已进入结构化 filter 白名单；当前查询尚未自动提取。 |
| `maintenance_stage` | VARCHAR | 已落地 | 维护阶段 | 已进入结构化 filter 白名单；当前查询尚未自动提取。 |
| `dense_vector` | FLOAT_VECTOR | 已落地 | chunk 检索文本稠密向量 | 用于语义相似度召回。 |
| `learned_sparse_vector` | SPARSE_FLOAT_VECTOR | 已落地 | BGE-M3 学习式稀疏向量 | 由应用的 BGE-M3 向量化节点生成，使用 `IP` 稀疏倒排索引；与 BM25 独立。 |

| `document_id` | VARCHAR | 已落地 | 所属文档 ID | 入库前由 `ImportGraphState.document_id` 回填；导入幂等、删除、重建索引的核心业务键。 |

| `source_title` | VARCHAR | 已落地 | 来源标题 | 当前使用 `file_title`，用于引用展示和兼容过渡。 |

chunk BM25 Function 契约：

| 项目 | 当前值 | 含义与边界 |
|---|---|---|
| Function 名称 | `chunk_lexical_text_bm25` | collection schema 内的 BM25 生成函数。 |

## Document 生命周期 API

| 接口/模型 | 状态 | 关键字段 | 含义 |
|---|---|---|---|
| `DELETE /documents/{document_id}` / `DeleteDocumentSchema` | 已落地 | `document_id`、`status`、`deleted_at` | 清理当前用户 document 的 chunk 和图片后执行 Mongo 软删除。 |
| `POST /documents/{document_id}/rebuild` / `RebuildDocumentSchema` | 已落地 | `task_id`、`document_id`、`dataset_id`、`index_version` | 复用原 document 创建 rebuild task，并通过后台任务重新执行导入图。 |
| `GET /documents` | 已落地 | `status` 查询参数 | 默认排除 deleted；显式传 `status=deleted` 可查看当前用户删除历史。 |

删除和重建都要求 `X-User-Id`。document 不存在或 owner 不匹配统一返回 404；deleted 或仍在 uploaded/processing 状态的 document 重建、处理中 document 删除返回 409。

## 查询 API

| 接口/模型 | 状态 | 关键字段 | 含义 |
|---|---|---|---|
| `POST /query` / `QueryRequestParam` | 阶段 5 第一、五部分已落地 | `X-User-Id`、`dataset_ids`、`query` | 在执行图前校验用户身份并写入用户、tenant、dataset 范围；同时从原始 query 提取规范化设备标识。 |
| `POST /query` / `QueryNotStreamResponse` | 阶段 5 第十一部分已落地 | `answer`、`trace_id`、`citations`、`terminal_reason_code` | 非流式查询直接返回答案、单次 Trace ID、结构化引用和终止原因码。 |
| SSE `FINAL` 事件 | 阶段 5 第十一部分已落地 | `answer`、`trace_id`、`citations`、`terminal_reason_code` | 流式内容完成后交付与非流式响应一致的最终元数据。 |
| `GET /query/status/{session_id}` / `QueryTaskStatusResponse` | 阶段 5 第十一部分已落地 | `status`、`answer`、`trace_id`、`citations`、`terminal_reason_code` | SSE 不可用时的轮询兜底；最终字段与 FINAL 事件对齐。 |
| `GET /query/history/{session_id}` / `HistoryResponse` | 阶段 5 第十一部分已落地 | `items[].citations`、`trace_id`、`terminal_reason_code` | 助手历史消息可重新展示当时引用；完整聊天历史权限隔离仍属于阶段 7。 |

`dataset_ids` 请求规则：

```text
字段省略        -> ["dataset_default_equipment_ops"]
显式 []/全空白 -> 422
重复值          -> 去空后保序去重
不同值超过 10 个 -> 422
```

聊天页使用与导入页相同的 `kb_user_id` localStorage key，并在 `POST /query` 时发送 `X-User-Id`。该轻量 ID 只用于当前阶段的数据归属，不是可信登录凭证。

## 状态枚举

### document/task 状态

| 值 | 含义 | 备注 |
|---|---|---|
| `pending` | 待处理 | task 初始状态，document 的解析/索引子状态也会使用。 |
| `uploaded` | 已上传 | document 上传完成，后台导入任务待处理。 |
| `processing` | 处理中 | 当前正在执行导入链路。 |
| `completed` | 已完成 | 对应阶段处理成功。 |
| `failed` | 已失败 | 对应阶段处理失败，查看 `failed_node` 和 `error_message`。 |
| `deleted` | 已删除 | Mongo document 软删除状态；Milvus chunk 和 MinIO 图片已完成清理。 |

### visibility

| 值 | 状态 | 含义 | 备注 |
|---|---|---|---|
| `private` | 已落地 | 仅 owner 可见 | 当前默认值。 |
| `shared` | 预留 | 指定成员或范围可见 | 阶段 7 以后再定义成员策略。 |
| `public` | 预留 | 公共可见 | Demo 公共知识库可使用。 |

### task_type

| 值 | 状态 | 含义 | 备注 |
|---|---|---|---|
| `import` | 已落地 | 普通上传导入任务 | 当前默认任务类型。 |
| `rebuild_index` | 已落地 | 重建索引任务 | 复用原 document，创建新 task，递增 `index_version`。 |
