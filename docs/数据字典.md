# 数据字典

## 维护说明

- MongoDB 和 Milvus 都不适合直接承载长期字段备注：Mongo 没有稳定的集合/字段注释机制，Milvus 的 schema description 更偏运行时结构说明。
- 本文档作为项目级数据字典，解释 Mongo 集合、Milvus collection 和关键字段含义。
- 后续 schema、字段含义或阶段状态发生变化时，应同步更新本文档。
- 字段状态说明：
  - `已落地`：当前代码或数据库记录中已经使用。
  - `阶段 4 计划`：阶段 4 方案中计划新增或调整，尚未全部落地。
  - `预留`：为后续权限、多租户、管理能力预留。

## Mongo 元数据

Mongo 元数据数据库：`ai_mfg_kb_meta`

当前主要集合：

| 集合 | 状态 | 含义 | 备注 |
|---|---|---|---|
| `datasets` | 已落地 | 知识库容器集合 | 当前默认知识库为公开 demo 知识库；阶段 7 已补齐 owner、visibility 和状态字段。 |
| `dataset_members` | 已落地 | 知识库成员集合 | 保存用户在 dataset 上的 viewer/editor/admin 轻量角色，用于 shared/private/public 管理策略。 |
| `documents` | 已落地 | 文档元数据集合 | 记录上传文件、解析状态、索引状态、用户归属和失败信息。 |
| `tasks` | 已落地 | 导入任务集合 | 记录导入、后续重建等任务进度和失败信息。 |
| `chat_message` | 已落地 | 聊天历史集合 | 阶段 7 起按 `user_id + session_id` 隔离；保存用户/助手消息，助手消息同时保存 Citation、Trace ID 和终止原因码。 |
| `retrieval_traces` | 已落地 | 单次查询检索轨迹集合 | 增量保存 Planner/Action/Observation、配置快照、用量、候选摘要、执行来源和最终引用；不保存 chunk 正文。 |

### datasets

一条记录表示一个知识库容器。

| 字段 | 类型/形态 | 状态 | 含义 | 备注 |
|---|---|---|---|---|
| `_id` | ObjectId | 已落地 | Mongo 内部主键 | 不作为业务关联字段。 |
| `dataset_id` | string | 已落地 | 知识库业务 ID | 当前默认值为 `dataset_default_equipment_ops`。 |
| `name` | string | 已落地 | 知识库名称 | 当前默认名称为“设备运维知识库”。 |
| `description` | string | 已落地 | 知识库说明 | 用于展示和排查。 |
| `owner_user_id` | string | 已落地 | Dataset 所属用户 | owner 自动拥有 admin 级管理权限；默认 demo dataset owner 为 `system_demo`。 |
| `tenant_id` | string | 已落地 | 租户 ID | 当前默认 `tenant_default`；仍是轻量单租户上下文，不是完整租户鉴权。 |
| `visibility` | string | 已落地 | Dataset 可见性 | 支持 `private/shared/public`；public 对当前用户可读，但不自动赋予写权限。 |
| `status` | string | 已落地 | Dataset 生命周期状态 | 当前支持 `active/deleted`；默认列表排除 deleted。 |
| `created_by_user_id` | string | 已落地 | 创建人用户 ID | 创建 dataset 时写入，后续 owner 变更不覆盖该字段。 |
| `created_at` | ISO datetime string | 已落地 | 创建时间 | UTC ISO 字符串。 |
| `updated_at` | ISO datetime string | 已落地 | 更新时间 | 创建、更新基础信息或默认 dataset 确认时写入。 |
| `deleted_at` | ISO datetime string | 已落地 | 删除时间 | 当前为后续软删除预留；空字符串表示未删除。 |

| `document_id` | string | 已落地 | 文档业务 ID | document 的稳定标识，chunk 已关联该字段。 |
| `dataset_id` | string | 已落地 | 所属知识库 ID | 关联 `datasets.dataset_id`。 |
| `owner_user_id` | string | 已落地 | 文档所属用户 | 阶段 3.5 引入，用于导入历史隔离。 |
| `tenant_id` | string | 已落地 | 租户 ID | 当前默认 `tenant_default`；用于 public/shared/private 轻量过滤，不是完整租户鉴权。 |
| `visibility` | string | 已落地 | 可见性 | 支持 `private/shared/public`；修改 completed 文档时需要重建索引同步 Milvus chunk 元数据。 |
| `latest_task_id` | string | 已落地 | 最新任务 ID | 指向该 document 最近一次导入或重建任务。 |
| `file_name` | string | 已落地 | 原始文件名 | 上传时的文件名。 |
| `file_path` | string | 已落地 | 原始文件本地路径 | 后续重建索引可复用。 |
| `local_dir` | string | 已落地 | 当前导入或重建任务工作目录 | 保存解析产物和中间文件；重建时更新为新 task 的工作目录。 |

| `subject_id` | string | 已落地 | 标准主题 ID | 关联 Milvus 标准主题和 chunk；Milvus 插入成功后随最终索引结果确认。 |

| `md_path` | string | 已落地 | 最终 Markdown 路径 | PDF 解析或 Markdown 图片增强后写入。 |
| `file_title` | string | 已落地 | 文件标题 | 通常来自文件名 stem，用于展示和主体识别兜底。 |
| `failed_node` | string | 已落地 | 失败节点 | 记录失败发生在哪个导入节点。 |
| `error_code` | string | 已落地 | 失败机器码 | 默认空字符串；服务重启中断固定为 `import_service_restarted`，供 API 和前端稳定识别，不依赖中文错误文案。 |
| `error_message` | string | 已落地 | 失败信息 | 面向排查的技术错误信息。 |
| `created_at` | ISO datetime string | 已落地 | 创建时间 | UTC ISO 字符串。 |
| `updated_at` | ISO datetime string | 已落地 | 更新时间 | 元数据状态变化时更新。 |

| `document_id` | string | 已落地 | 关联文档 ID | 关联 `documents.document_id`。 |
| `dataset_id` | string | 已落地 | 所属知识库 ID | 关联 `datasets.dataset_id`。 |

| `task_type` | string | 已落地 | 任务类型 | 支持普通导入 `import` 和重建索引 `rebuild_index`；权限字段同步当前复用 `rebuild_index`。 |

| `error_message` | string | 已落地 | 失败信息 | 面向排查的技术错误信息。 |
| `created_at` | ISO datetime string | 已落地 | 创建时间 | UTC ISO 字符串。 |
| `updated_at` | ISO datetime string | 已落地 | 更新时间 | 状态或节点进度变化时更新。 |
| `completed_at` | ISO datetime string | 已落地 | 完成时间 | 任务完成时写入。 |
| `failed_at` | ISO datetime string | 已落地 | 失败时间 | 任务失败时写入。 |
| `task_type=rebuild_index` | enum value | 已落地 | 重建索引任务类型 | 任务类型枚举值，持久记录；运行进度仍由 `status` 表达。 |

#### 导入服务重启收口规则

导入任务当前由 FastAPI 进程内的后台任务执行，不具备断点续跑能力。服务启动进入 lifespan 时，仓储会查询 `tasks.status in [pending, processing]` 的遗留任务，并把已经失去执行者的任务收口为持久终态：

- document 的 `latest_task_id` 已不是该 task 时，只更新旧 task，绝不覆盖新任务持有的 document 状态。
- document 已经 `status=completed` 且 `index_status=completed` 时，说明最终入库已提交，仅 task 终态漏写；task 修复为 `completed`。
- 其他遗留 task 写入 `status=failed`、`error_code=import_service_restarted`、固定 `error_message`、`failed_at/updated_at`，并清空 `running_nodes`、保留 `done_nodes`。
- `failed_node` 取中断前最后一个运行节点；解析节点同步令 `parse_status=failed`，索引节点同步令 `index_status=failed`。没有运行节点时不猜测失败阶段。
- 更新带状态和 `latest_task_id` 条件，重复启动不会反复改写已收口记录。
- `tasks.status` 建有普通索引，避免每次启动扫描整个任务集合。

### chunk_status_events

一条记录表示一次 chunk 启用或禁用事件。该集合用于审计和后续阶段 8 数据筛选，不作为
当前状态查询的唯一来源；当前状态由 `chunk_status_overrides` 保存。

| 字段 | 类型/形态 | 状态 | 含义 | 备注 |
|---|---|---|---|---|
| `event_id` | string | 已落地 | 事件唯一 ID | service 生成 UUID，Mongo 建唯一索引。 |
| `document_id` / `chunk_id` / `index_version` | string / string\|int / int | 已落地 | chunk 版本身份 | 三者共同避免重建索引后把旧标注套到新 chunk。 |
| `dataset_id` | string | 已落地 | 所属知识库 | 用于后续统计和数据筛选。 |
| `owner_user_id` / `tenant_id` / `visibility` | string | 已落地 | chunk 归属和可见性快照 | 记录事件发生时的权限上下文。 |
| `operator_user_id` | string | 已落地 | 操作人 | 阶段 7 起允许 document owner 或 dataset editor/admin 启停 chunk。 |
| `operation` | enum | 已落地 | `enable` 或 `disable` | 表示本次操作方向。 |
| `previous_enabled` / `enabled` | bool | 已落地 | 操作前后有效状态 | 禁用事件必须从 true 到 false，启用事件必须从 false 到 true。 |
| `reason_type` | enum | 已落地 | 机器可读原因 | 支持 `parse_error/header_footer/garbled_text/outdated_content/human_misjudgment/manual_restore/other`。 |
| `reason_detail` | string | 已落地 | 人工补充说明 | `other` 必填。 |
| `source` | enum | 已落地 | 事件来源 | 当前前端/API 写 `manual`。 |
| `human_confirmed` | bool | 已落地 | 是否人工确认 | 可作为弱质量信号，不能未经复核直接作为 GRPO reward。 |
| `trace_id` | string \| null | 已落地 | 关联查询 Trace | 普通文档列表操作通常为空。 |
| `created_at` | ISO datetime string | 已落地 | 事件创建时间 | 用于审计排序。 |

主要索引：`event_id` 唯一索引、`document_id + chunk_id + index_version + created_at`、
`operator_user_id + created_at`、`reason_type + created_at`、
`dataset_id + human_confirmed + reason_type + created_at`。

### chunk_status_overrides

路线 B 的当前人工覆盖层。Milvus chunk 原始 row 不修改，Mongo 只记录人工判断是否要额外
排除或恢复某个 chunk。

| 字段 | 类型/形态 | 状态 | 含义 | 备注 |
|---|---|---|---|---|
| `document_id` / `chunk_id` / `index_version` | string / string\|int / int | 已落地 | 覆盖状态身份 | Mongo 建唯一索引，保证同一版本 chunk 只有一条当前覆盖。 |
| `dataset_id` | string | 已落地 | 所属知识库 | 查询侧按当前 dataset 范围读取禁用 ID。 |
| `owner_user_id` / `tenant_id` / `visibility` | string | 已落地 | 可见性快照 | 查询侧读取 disabled ID 时继续按 public/shared/owner 边界过滤。 |
| `manual_status` | enum | 已落地 | 当前人工覆盖状态 | `disabled` 表示人工禁用；`enabled` 表示人工恢复；`none` 表示无覆盖。 |
| `latest_event_id` | string | 已落地 | 最近一次审计事件 ID | 关联 `chunk_status_events.event_id`。 |
| `updated_at` | ISO datetime string | 已落地 | 当前覆盖更新时间 | 每次 set override 时更新。 |

查询侧只读取 `manual_status=disabled`，再追加到 Milvus 表达式：

```text
enabled == true AND chunk_id not in [...]
```

这不是第二个 Mongo `enabled == true` 白名单；没有 override 的正常 chunk 仍可按 Milvus
`enabled == true` 参与召回。

这里的 `error_code` 是给程序判断的稳定英文标识，`error_message` 是给用户和运维查看的中文说明。新任务、重建任务和成功终态都会清空旧 `error_code`。

启动收口采用“失败不阻断服务”的边界：Mongo 暂时不可用时记录错误日志，FastAPI 仍继续启动。模块 import 阶段仍不会连接 Mongo；连接只发生在 lifespan 启动收口或后续首次仓储访问时。

### chat_message

一条记录表示聊天会话中的一条用户或助手消息。`session_id` 由前端生成，只用于把多轮消息归为同一会话；真正的轻量权限边界是 `user_id + session_id`。

| 字段 | 类型/形态 | 状态 | 含义 | 备注 |
|---|---|---|---|---|
| `_id` | ObjectId | 已落地 | Mongo 内部主键 | API 返回时转为字符串 `id`。 |
| `user_id` | string | 已落地 | 消息所属用户 | 阶段 7 起新增；查询历史、列会话和删除会话都必须按它过滤。 |
| `session_id` | string | 已落地 | 会话 ID | 不具备权限含义；不同用户可以有相同 session_id。 |
| `role` | enum string | 已落地 | 消息角色 | `user` 表示用户消息；`assistant` 表示助手消息。 |

### retrieval_traces

一条记录表示一次查询执行的可重放检索轨迹。`trace_id` 是单次执行 ID，`session_id` 是聊天会话 ID；一个会话可以包含多条 Trace。

| `planner_steps` | list[`TracePlannerStep`] | 已落地 | 按顺序保存的 Decision/Action/Observation | Planner 决定后先增量写 pending，Action 完成后覆盖同一 step 为 completed/failed。 |
| `channel_hits` | list[`TraceChannelHit`] | 已落地 | 各已执行检索 Action 的候选摘要 | 保存 ID、排名、分数、编号、`enabled`、召回通道、是否进入 rerank、是否成为 Citation 和 SHA-256；不保存 chunk 正文。 |
| `final_citations` | list[`Citation`] | 已落地 | 真正进入最终答案上下文的引用 | 追问、拒答和答案模型失败时为空。 |
| `status` / `terminal_action` / `terminal_reason_code` | enum | 已落地 | Trace 状态和最终决策 | `running` 在入口创建；正常终止写 `completed`；未收口异常写 `failed`。 |

`retrieval_traces` 在模块 import 时不连接 Mongo，只在真实 HTTP 查询开启 `trace_persistence_enabled` 后懒加载仓储。Trace 写入失败会记录日志，不应遮蔽本来可正常交付的答案。

`TraceChannelHit.enabled` 表示候选进入查询链路时携带的启用状态。本地 chunk 必须是
bool，Web 候选没有本地启停状态，记录为 null。阶段 6 任务 8 已在查询过滤前读取
Mongo 人工禁用覆盖层；被 `manual_status=disabled` 排除的 chunk 不会进入候选列表，
因此也不会生成 `TraceChannelHit`。Trace 仍只保存候选摘要，不保存完整 chunk 正文。

## 查询图运行时状态

`QueryGraphState` 是一次查询进入 LangGraph 后的运行时状态，不是 Mongo 持久化记录。阶段 5 第三部分补齐 Planner/Observation/引用字段，第四部分统一权限 filter，第五部分接入设备标识与编号 Observation，第六部分统一 original、HyDE、Web 的候选契约、两层 RRF 和 rerank 元数据，第七部分补齐 chunk 的 learned sparse/BM25 实验 schema，第八部分实现确定性 RuleBasedPlanner，第九部分接入真实查询图，第十至十二部分已经完成 Mongo Retrieval Trace、结构化 Citation 输出和配置快照持久化。

| state 字段 | 类型/默认值 | 来源/写入方 | 含义与边界 |
|---|---|---|---|

### 统一 Milvus 查询过滤契约

查询 State 中与阶段 6 启停过滤相关的运行时字段：

| 字段 | 类型 | 状态 | 含义 |
|---|---|---|---|
| `chunk_status_filter_enabled` | bool | 已落地 | 是否启用路线 B 的 Mongo 人工禁用过滤。真实 HTTP 查询入口写 `true`；无 Mongo 的单元测试和离线重放默认 `false`。 |
| `disabled_chunk_ids` | list[int\|string] | 已落地 | 当前查询范围内 `chunk_status_overrides.manual_status=disabled` 的 chunk_id 快照；只用于本次 Milvus expr，不代表全库禁用状态。 |

| 函数 | 状态 | 输入 | 输出与边界 |
|---|---|---|---|
| `build_chunk_access_filter` | 已落地 | `dataset_ids`、`owner_user_id`、`tenant_id` | 输出 dataset、`enabled == true` 和 public/shared/owner 可见性条件；三个 OR 分支始终使用完整括号。 |
| `build_structured_identifier_filter` | 已落地 | `query_identifiers` | 可选输出设备运维精确字段条件；未知 schema 字段和显式空值拒绝，不把字典 key 直接拼入 expr。 |
| `select_structured_query_identifiers` | 已落地 | 完整查询标识字典 | 只选择当前 Milvus schema 可映射字段；允许 `sop_code/part_number` 留在 State 和检索文本，但不伪造字段条件。 |
| `get_disabled_chunk_ids_for_query` | 已落地 | `QueryGraphState`、可选 repository | 开启 `chunk_status_filter_enabled` 时读取 Mongo `manual_status=disabled` 的 chunk_id；关闭时返回空列表且不访问 Mongo。 |
| `build_disabled_chunk_exclusion_filter` | 已落地 | `disabled_chunk_ids` | 生成 `chunk_id not in [...]`；空列表返回空字符串，不拼 `not in []`。 |
| `build_chunk_retrieval_filter` | 已落地 | access 输入、`subject_ids`、可选标识、可选 `disabled_chunk_ids` | 合并为所有本地召回通道使用的最终 expr；dataset/subject 为空时禁止全库搜索，并在路线 B 下追加人工禁用排除条件。 |
| `build_chunk_retrieval_filter_from_state` | 已落地 | `QueryGraphState` | 普通检索、HyDE 读取过滤上下文的唯一适配入口；读取 `disabled_chunk_ids` 快照，不回退匿名用户或默认范围。 |

可见性规则：

```text
dataset_id in 当前 dataset_ids
AND subject_id in 已确认 subject_ids
AND enabled == true
AND (
    visibility == "public"
    OR (visibility == "shared" AND tenant_id == 当前 tenant_id)
    OR owner_user_id == 当前 owner_user_id
)
AND chunk_id not in 当前 Mongo 人工禁用 chunk_id 列表  # 仅列表非空时追加
```

动态字符串统一去除首尾空白、保序去重并进行 Milvus 引号/反斜杠/换行转义。当前结构化标识白名单只包含 chunk schema 已存在的 `equipment_model`、`alarm_code`、`part_name`、`sop_type`、`safety_level`、`maintenance_stage`。第五部分已经自动提取 `equipment_model`、`alarm_code`、`sop_code` 和带明确上下文的 `part_number`；其中后两者当前只进入增强检索文本，不进入 Milvus 字段表达式。

普通检索、HyDE 以及同一次 hybrid search 内的所有请求共享同一 expr。第六部分已能按 `RetrievalMode` 创建 dense/learned sparse/BM25 请求，并让 chunk collection 使用 `RRFRanker(k=60)`；第七部分已补齐 `learned_sparse_vector`、`lexical_text`、`bm25_sparse_vector` 和 BM25 Function。四轮固定评测后默认选择三路 C；A/B 继续用于离线回归和受控诊断，不改变线上默认配置。

两段式检索的第二段只允许移除结构化标识条件，不能移除权限、dataset、subject 或 `enabled`。宽松召回后如果正文仍命中用户原编号，可标记 `fallback_exact_match` 并继续作为证据；如果只找到不同编号，必须标记 `suggestion_required`、写入 `suggested_identifiers` 并追问用户，不能进入答案 Citation。

阶段 4 已将 chunk 从文件标题维度升级到 document 维度。当前不做旧 schema 在线兼容；本地或测试 Milvus 集合如果仍是旧字段结构，可以删除集合后由导入流程重建。

| 字段 | 类型/形态 | 状态 | 含义 | 备注 |
|---|---|---|---|---|
| `chunk_id` | INT64 auto_id primary key | 已落地 | Milvus 自动生成的 chunk 主键 | 用于返回检索命中的切片标识，不作为业务幂等键。 |
| `content` | VARCHAR | 已落地 | 切片正文内容 | 答案生成阶段主要依据该字段组织回答。 |
| `file_title` | VARCHAR | 已落地 | 来源文件标题 | 仅作为展示和兼容字段，不再作为导入幂等删除条件。 |
| `title` | VARCHAR | 已落地 | 当前切片标题 | 通常来自 Markdown 标题。 |
| `parent_title` | VARCHAR | 已落地 | 父级标题 | 保留章节层级，帮助定位切片上下文。 |
| `part` | INT8 | 已落地 | 分片顺序标记 | 表示该 chunk 在章节拆分结果中的顺序。 |
| `subject_id` | VARCHAR | 已落地 | 标准主题 ID | 阶段 2 后查询优先用该字段过滤 chunk。 |
| `standard_subject_name` | VARCHAR | 已落地 | 标准主题名称 | 可读展示字段，检索过滤不依赖该字段。 |
| `equipment_model` | VARCHAR | 已落地 | 设备型号 | 已进入结构化 filter 白名单；查询入口把 `HAK180/HAK-180/HAK 180` 统一为 `HAK 180` 后精确过滤。 |
| `alarm_code` | VARCHAR | 已落地 | 报警码或故障码 | 已进入结构化 filter 白名单；查询入口独立提取 E020/E021，禁止用向量相似度自动互相纠正。 |
| `part_name` | VARCHAR | 已落地 | 部件名称 | 已进入结构化 filter 白名单；当前查询尚未自动提取。 |
| `sop_type` | VARCHAR | 已落地 | SOP 类型 | 已进入结构化 filter 白名单；字段表达 SOP 类型，不等同于尚未定义的 SOP 编号。 |
| `safety_level` | VARCHAR | 已落地 | 安全等级或风险级别 | 已进入结构化 filter 白名单；当前查询尚未自动提取。 |
| `maintenance_stage` | VARCHAR | 已落地 | 维护阶段 | 已进入结构化 filter 白名单；当前查询尚未自动提取。 |
| `dense_vector` | FLOAT_VECTOR | 已落地 | chunk 检索文本稠密向量 | 用于语义相似度召回。 |
| `learned_sparse_vector` | SPARSE_FLOAT_VECTOR | 已落地 | BGE-M3 学习式稀疏向量 | 由应用的 BGE-M3 向量化节点生成，使用 `IP` 稀疏倒排索引；与 BM25 独立。 |
| `lexical_text` | VARCHAR | 已落地 | BM25 词法检索输入 | 应用按固定字段顺序拼接主题、设备标识、标题和正文并追加编号变体；启用 `jieba + cnalphanumonly + lowercase` Analyzer。 |
| `bm25_sparse_vector` | SPARSE_FLOAT_VECTOR | 已落地 | Milvus BM25 稀疏向量 | 由 `chunk_lexical_text_bm25` Function 根据 `lexical_text` 自动生成；应用禁止写入，索引 metric 为 `BM25`。 |
| `dataset_id` | VARCHAR | 已落地 | 所属知识库 ID | 入库前由 `ImportGraphState.dataset_id` 回填；阶段 5 普通检索与 HyDE 已强制按当前 `dataset_ids` 过滤。 |
| `document_id` | VARCHAR | 已落地 | 所属文档 ID | 入库前由 `ImportGraphState.document_id` 回填；导入幂等、删除、重建索引的核心业务键。 |
| `owner_user_id` | VARCHAR | 已落地 | 所属用户 ID | 入库前由 `ImportGraphState.owner_user_id` 回填；阶段 5 本地召回只允许当前 owner 访问私有数据。 |
| `tenant_id` | VARCHAR | 已落地 | 租户 ID | 入库前由 `ImportGraphState.tenant_id` 回填；shared 数据只允许相同 tenant 访问。 |
| `visibility` | VARCHAR | 已落地 | 可见性 | 入库默认 `private`；本地召回区分 `public`、同 tenant `shared` 和 owner 可见数据。 |
| `index_version` | INT64 | 已落地 | 文档级检索索引产物版本 | 入库前由 `ImportGraphState.index_version` 回填；表示该 document 的 chunk/vector 入库版本。 |
| `chunk_index` | INT64 | 已落地 | document 内 chunk 顺序 | 入库前按最终 chunks 顺序从 `0` 递增。 |
| `enabled` | BOOL | 已落地 | chunk 是否启用 | 当前入库默认 `true`；阶段 5 本地召回已强制 `enabled == true`。阶段 6 路线 B 不直接改 Milvus 字段，查询侧额外用 Mongo `manual_status=disabled` 的 `chunk_id not in [...]` 排除人工禁用 chunk。 |
| `source_title` | VARCHAR | 已落地 | 来源标题 | 当前使用 `file_title`，用于引用展示和兼容过渡。 |

chunk BM25 Function 契约：

| 项目 | 当前值 | 含义与边界 |
|---|---|---|
| Function 名称 | `chunk_lexical_text_bm25` | collection schema 内的 BM25 生成函数。 |
| input | `lexical_text` | 应用唯一需要写入的 BM25 原始文本。 |
| output | `bm25_sparse_vector` | Milvus 自动生成，不能出现在应用插入数据中。 |
| Analyzer 校验 | 建库前调用 `run_analyzer` | 至少要求保留 `hak180`、`e021` 和中文 token；失败时中止建库。 |
| 旧 schema 行为 | 明确报错并要求删 collection 重建 | 当前仅有可丢弃测试数据，不实现 `sparse_vector` backfill、双写或在线迁移。 |

| `POST /documents/{document_id}/rebuild` / `RebuildDocumentSchema` | 已落地 | `task_id`、`document_id`、`dataset_id`、`index_version` | 复用原 document 创建 rebuild task，并通过后台任务重新执行导入图。 |

## Chunk 管理 API

阶段 6 已提供轻量 chunk 查看与启停接口，服务于人工质检和演示闭环，不提供正文编辑或重新向量化。

| 接口/模型 | 状态 | 关键字段 | 含义 |
|---|---|---|---|
| `GET /documents/{document_id}/chunks` / `ChunkListSchema` | 已落地 | `enabled=all/true/false`、`items[].content_preview`、`items[].effective_enabled` | 按 document 查看当前版本 chunk。列表只返回正文预览，不返回向量和完整正文。 |
| `GET /chunks` / `ChunkListSchema` | 已落地 | `dataset_id`、`document_id`、`enabled`、`keyword` | 跨 document 查询当前用户可见 chunk，用于后续管理台筛选。 |
| `GET /documents/{document_id}/chunks/{chunk_id}` / `ChunkDetailSchema` | 已落地 | `content`、`manual_status`、`latest_event` | 查看单个 chunk 详情和完整正文；仍不作为编辑入口。 |
| `PATCH /documents/{document_id}/chunks/{chunk_id}/enabled` / `ChunkStatusChangeRequest` | 已落地 | `enabled`、`expected_index_version`、`reason_type`、`reason_detail` | 启用或禁用 chunk；阶段 6 走路线 B，只写 Mongo event/override，不修改 Milvus 原 row。 |
| `PATCH /chunks/enabled` / `ChunkBatchStatusChangeRequest` | 已落地 | `items[]`、`reason_type`、`reason_detail` | 批量启用或禁用 chunk；每项仍校验 document、chunk 和 index_version。 |
| `GET /documents/{document_id}/chunks/{chunk_id}/events` / `ChunkEventListSchema` | 已落地 | `items[].operation`、`reason_type`、`operator_user_id` | 查看某个 chunk 的启停审计历史。 |

前端入口：`app/resources/http/import.html` 的“我的导入记录”中，completed 且 `chunk_count > 0`
的文档会显示 `Chunk` 按钮。展开后调用 `/documents/{document_id}/chunks`，展示启用/禁用
状态、人工覆盖状态和正文预览；启用/禁用按钮调用 PATCH API。HTTP 403/404/409/500 等
失败会优先展示后端返回的中文 `detail`。

权限边界：

- 查看列表、详情和事件按 document 可见性过滤。
- 启停操作允许 document owner，或具备该 dataset `editor/admin` 角色的成员；public/shared 只读用户不能启停。
- `expected_index_version` 不一致返回 409，避免把旧版本人工标注套到新索引结果。
- `manual_status=disabled` 时 `effective_enabled=false`；Milvus `enabled=false` 的 chunk 不能被路线 B 强行恢复为可召回。

## 状态枚举

### document/task 状态

| 值 | 含义 | 备注 |
|---|---|---|
| `pending` | 待处理 | task 初始状态，document 的解析/索引子状态也会使用。 |
| `uploaded` | 已上传 | document 上传完成，后台导入任务待处理。 |
| `processing` | 处理中 | 当前正在执行导入链路。 |
| `completed` | 已完成 | 对应阶段处理成功。 |
| `failed` | 已失败 | 对应阶段处理失败，查看 `failed_node` 和 `error_message`。 |
| `deleted` | 已删除 | Mongo document 软删除状态；Milvus chunk 和 MinIO 图片已完成清理。 |

### visibility

| 值 | 状态 | 含义 | 备注 |
|---|---|---|---|
| `private` | 已落地 | 仅 owner 和显式成员可见 | 新建 dataset/document 默认值。 |
| `shared` | 已落地 | 指定成员共享可见 | 阶段 7 第一版通过 `dataset_members` 收紧写权限；不再把 tenant 内所有人当作可编辑用户。 |
| `public` | 已落地 | 公共可读 | 任何当前用户可读，但不自动获得写权限。 |

### dataset member role

| 值 | 状态 | 含义 | 备注 |
|---|---|---|---|
| `viewer` | 已落地 | 查看者 | 可读取可见 dataset/document/chunk。 |
| `editor` | 已落地 | 编辑者 | 可上传、修改自己可写范围内的 document，并可启停 chunk。 |
| `admin` | 已落地 | 管理员 | 可修改 dataset 元数据和管理 members。 |

### task_type

| 值 | 状态 | 含义 | 备注 |
|---|---|---|---|
| `import` | 已落地 | 普通上传导入任务 | 当前默认任务类型。 |
| `rebuild_index` | 已落地 | 重建索引任务 | 复用原 document，创建新 task，递增 `index_version`。 |
| `access_sync` | 预留 | 权限同步任务 | 当前 completed 文档 owner/visibility 修改复用 `rebuild_index` 同步 Milvus 元数据，暂不单独创建该类型任务。 |

### access_sync_status

| 值 | 状态 | 含义 | 备注 |
|---|---|---|---|
| `none` | 已落地 | 不需要同步 | 默认状态。 |
| `pending` | 已落地 | 等待同步 | 修改 completed 文档 owner/visibility 后创建重建任务时写入。 |
| `processing` | 预留 | 同步中 | 后续可由后台任务细化状态。 |
| `completed` | 已落地 | 已同步 | 未入库或失败文档可直接完成元数据修改；重建完成后也可写回。 |
