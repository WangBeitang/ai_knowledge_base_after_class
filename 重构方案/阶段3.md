# 阶段 3：文档与任务元数据闭环

## Summary
- 新增 Mongo 持久化元数据：`datasets`、`documents`、`tasks`。
- 导入任务不再只依赖 `task_utils` 内存字典；内存继续用于即时进度/SSE，Mongo 作为长期状态源。
- 不做旧数据迁移和兼容逻辑；Mongo 测试数据可直接删库或删集合重建。
- 阶段 3 只补文档/任务状态闭环，不提前做阶段 4 的 chunk 幂等、删除、重建索引。

## Key Changes
- 新增 `app/infra/persistence/import_metadata_repository.py`：
  - 懒加载 Mongo，不影响现有 graph compile 测试。
  - `datasets`：默认创建 `dataset_default_equipment_ops`，名称为“设备运维知识库”。
  - `documents`：记录 `document_id`、`dataset_id`、`task_id`、文件名、路径、`status`、`parse_status`、`index_status`、`chunk_count`、失败节点和错误信息。
  - `tasks`：记录 `task_id`、`document_id`、`dataset_id`、`task_type=import`、`status`、`running_nodes`、`done_nodes`、`failed_node`、`error_message`。
- 扩展导入状态契约：
  - `ImportGraphState` 原本已有 `task_id`，阶段 3 新增 `dataset_id`、`document_id`。
  - `task_id` 表示一次任务执行，`document_id` 表示被处理的文档，`dataset_id` 表示所属知识库。
  - `POST /upload` 沿用原有 task_id 生成逻辑，阶段 3 新增 document_id。 当前单知识库版本使用默认 dataset_id，并确保默认 dataset 存在。 后续多知识库版本中，upload 应指定已有 dataset_id，再创建 document/task 元数据。
- 改造状态推进：
  - `task_utils` 保留内存状态，但对已注册的导入任务同步写 Mongo。
  - 每个导入节点的 running/done 继续走现有 `add_running_task/add_done_task`。
  - 关键节点额外回写 document 元数据：切分完成写 `chunk_count`，主体识别写 `subject_id/standard_subject_name`，Milvus 入库完成写 `index_status=completed`。
- 改造导入 API：
  - `UploadSchema` 增加 `dataset_id`、`document_ids`。
  - `TaskStatusSchema` 增加 `document_id`、`dataset_id`、`failed_node`、`error_message`、`created_at`、`updated_at`。
  - `GET /status/{task_id}` 优先读 Mongo；没有持久化记录时再回退内存状态。
  - 新增 `GET /documents/{document_id}` 查询文档状态。
- 失败处理：
  - 后台导入异常时，根据当前 running 节点记录 `failed_node`。
  - 同步更新 task/document 为 `failed`，写入 `error_message`。
  - 解析阶段失败写 `parse_status=failed`；主体识别、向量化、Milvus 入库失败写 `index_status=failed`。

## Public Interface
- `POST /upload` 响应：
  - 保留 `task_ids`。
  - 新增 `document_ids`、`dataset_id`。
- `GET /status/{task_id}` 响应：
  - 保留 `status`、`done_list`、`running_list`，保证现有 `import.html` 仍可展示进度。
  - 新增持久化字段：`document_id`、`dataset_id`、`failed_node`、`error_message`。
- `GET /documents/{document_id}` 响应：
  - 返回文档整体状态、解析状态、索引状态、chunk 数量、失败节点、错误信息、主题信息。

## Test Plan
- 新增 repository 单元测试：验证默认 dataset 创建、document/task 创建、状态更新、失败信息写入。
- 新增 `task_utils` 测试：验证导入任务会写 Mongo，普通查询 session 不触发 Mongo。
- 新增 API schema/状态测试：验证 `/status/{task_id}` 能从持久化记录恢复历史任务状态。
- 保留并跑全量回归：`uv run python -m pytest`。当前基线已确认是 `38 passed`。

## Assumptions
- 不迁移旧 Mongo 数据，不兼容旧 document/task 结构。
- 默认只做一个 dataset：“设备运维知识库”；完整 Dataset 管理 API 留到阶段 7。
- 阶段 3 不改变 Milvus chunk schema 的幂等策略；按 `document_id` 入库、删除、重建放到阶段 4。
