## 一、这部分到底要实现什么

第五部分不再重新实现 PDF 解析、图片增强、切分、主题识别、Embedding 和 Milvus 入库。

前四部分已经具备的底层能力：

- document/task 元数据和用户归属。
- rebuild task 元数据创建、`index_version + 1`。
- 图片资源按 `document_id` 使用独立 MinIO 前缀。
- chunk 按 `document_id` 删除旧数据并插入新数据。
- Milvus 插入成功后的 document 索引元数据回写。
- 导入异常后的 task/document failed 收口。

第五部分需要完成的是：

```text
HTTP API
    -> document 生命周期 service
        -> Mongo repository
        -> Milvus chunk 删除
        -> MinIO 图片前缀删除
        -> 已有导入图后台执行入口
```

本部分不做：

- 不删除 `STANDARD_SUBJECT_COLLECTION` 和 `SUBJECT_ALIAS_COLLECTION`。它们是全局知识体系，不属于单个 document。
- 不物理删除 Mongo document/task，保留历史与审计信息。
- 不做旧 schema 兼容或历史数据迁移。
- 不做前端按钮；前端轻量入口属于第六部分。
- 不物理删除原始上传文件和本地解析产物；后续如需释放磁盘，应单独定义保留周期。

## 三、最终调用链

### 3.1 删除 document

```text
DELETE /documents/{document_id}
    -> 从 X-User-Id 获取 owner_user_id
    -> service 按 document_id + owner_user_id 查询 document
    -> 删除 CHUNKS_COLLECTION 中该 document 的 chunk
    -> 删除 document.image_prefix 下的 MinIO 对象
    -> Mongo document 软删除：status=deleted、deleted_at=当前时间
    -> 返回删除结果
```

建议采用“先清理外部资源，最后写 Mongo 删除状态”的顺序。这样只要 API 返回成功，就能保证 chunk 和图片都已清理。

如果中间失败，不写 `status=deleted`。调用方可以重试；Milvus delete 和 MinIO 空前缀删除都应保持幂等。

### 3.2 重建索引

```text
POST /documents/{document_id}/rebuild
    -> 从 X-User-Id 获取 owner_user_id
    -> service 校验 document、删除状态、原始文件
    -> 创建新 task_id 和新工作目录
    -> repository 创建 rebuild_index task
       同时 latest_task_id 更新、index_version + 1
    -> 注册 persistent task
    -> BackgroundTasks 调用已有 invoke_graph
    -> 导入图重新执行解析、切分、Embedding、Milvus 替换
```

普通重新上传与重建必须继续区分：

```text
普通上传：新 document_id + 新 task_id + index_version=1
重建索引：原 document_id + 新 task_id + index_version+1
```

### 4.1 默认列表隐藏 deleted document

修改 `ImportMetadataRepository.list_documents`。

目标：

- 不传 `status`：自动排除 deleted。
- 显式传 `status=deleted`：只返回 deleted。
- owner、dataset、keyword 过滤保持不变。

参考代码：

```python
def list_documents(
    self,
    *,
    owner_user_id: str,
    dataset_id: str = DEFAULT_DATASET_ID,
    status: str | None = None,
    keyword: str | None = None,
    limit: int = 20,
) -> list[dict[str, Any]]:
    query: dict[str, Any] = {
        "owner_user_id": owner_user_id,
        "dataset_id": dataset_id,
    }

    if status:
        # 调用方显式指定状态时，严格按指定状态查询。
        # 因此 GET /documents?status=deleted 可以查看自己的删除历史。
        query["status"] = status
    else:
        # 默认列表是“当前有效文档”，软删除记录不应继续出现在主列表中。
        query["status"] = {"$ne": STATUS_DELETED}

    if keyword:
        query["file_name"] = {"$regex": keyword, "$options": "i"}

    cursor = self.documents.find(query).sort("updated_at", DESCENDING).limit(limit)
    return [_without_mongo_id(document) or {} for document in cursor]
```

### 4.2 新增 document 软删除方法

建议在 repository 中增加：

```python
def mark_document_deleted(
    self,
    *,
    document_id: str,
    owner_user_id: str,
) -> dict[str, Any]:
    """
    将当前用户拥有的 document 标记为已删除。

    repository 只负责 Mongo 状态，不负责删除 Milvus chunk 或 MinIO 图片。
    owner_user_id 必须进入查询条件，不能先按 document_id 查出记录后无条件更新。
    """
    document = self.get_document(document_id, owner_user_id)
    if not document:
        raise ValueError(f"document_id={document_id} 不存在")

    # 同一用户重复调用删除时直接返回已有结果，使 DELETE 操作可以安全重试。
    if document.get("status") == STATUS_DELETED:
        return document

    now = _now_iso()
    payload = {
        "status": STATUS_DELETED,
        "deleted_at": now,
        "updated_at": now,
    }
    self.documents.update_one(
        {
            "document_id": document_id,
            "owner_user_id": owner_user_id,
        },
        {"$set": payload},
    )
    return {**document, **payload}
```

这里不要清空 `latest_task_id`、`subject_id`、原文件路径或历史状态。软删除的价值就是保留排查信息。

## 五、第二步：补 MinIO 图片前缀删除

### 5.1 在 gateway 中封装删除方法

不要让 API 或 service 直接操作 MinIO SDK。修改 `app/infra/object_storage/minio_gateway.py`：

```python
from minio.deleteobjects import DeleteObject


class MinioGateway:
    ...

    def delete_image_prefix(self, image_prefix: str) -> int:
        """
        删除一个 document 图片前缀下的全部对象，返回删除对象数量。

        空前缀直接返回 0，避免错误地扫描整个 bucket。
        前缀末尾补 `/`，防止删除 `kb-images/doc_1` 时误匹配 `kb-images/doc_10`。
        """
        normalized_prefix = str(image_prefix or "").strip("/")
        if not normalized_prefix:
            return 0

        object_prefix = f"{normalized_prefix}/"
        client = self.client()
        objects = list(
            client.list_objects(
                bucket_name=self.bucket_name,
                prefix=object_prefix,
                recursive=True,
            )
        )
        if not objects:
            return 0

        delete_objects = [DeleteObject(item.object_name) for item in objects]
        errors = list(
            client.remove_objects(
                bucket_name=self.bucket_name,
                delete_object_list=delete_objects,
            )
        )
        if errors:
            error_text = "; ".join(str(error) for error in errors)
            raise RuntimeError(f"删除 MinIO 图片前缀失败，prefix={object_prefix}, errors={error_text}")

        return len(delete_objects)
```

### 6.2 删除 service

```python
def delete_document(document_id: str, owner_user_id: str) -> dict:
    """
    删除当前用户自己的 document 检索产物，并将 Mongo document 软删除。

    执行顺序很重要：先清理 Milvus/MinIO，最后写 Mongo deleted。
    外部资源清理失败时保留非 deleted 状态，调用方可以安全重试。
    """
    repo = get_import_metadata_repository()
    document = repo.get_document(document_id, owner_user_id)
    if not document:
        # get_document 同时按 document_id 和 owner_user_id 查询。
        # 因此“不存在”和“属于其他用户”统一表现为 404，避免泄露资源存在性。
        raise DocumentNotFoundError(f"document_id={document_id} 不存在")

    if document.get("status") == STATUS_DELETED:
        # DELETE 保持幂等。同一 owner 重复删除直接返回已有软删除记录。
        return document

    if document.get("status") not in {STATUS_COMPLETED, STATUS_FAILED}:
        # uploaded/processing 状态说明旧导入任务仍可能继续运行。此时删除会产生竞态：
        # service 刚删完 chunk，旧任务又把 chunk 插回并将 document 改回 completed。
        raise DocumentStateError(
            f"document_id={document_id} 当前正在处理，不能删除"
        )

    # 这里只删除 chunk collection。标准主题和别名是全局知识体系，不能随单个
    # document 删除，否则可能破坏其他 document 共用的 subject_id。
    remove_old_chunks(document_id)

    # 无图片 document 的 image_prefix 为空，gateway 会安全返回 0。
    minio_gateway.delete_image_prefix(document.get("image_prefix", ""))

    return repo.mark_document_deleted(
        document_id=document_id,
        owner_user_id=owner_user_id,
    )
```

### 6.3 重建准备 service

```python
def prepare_document_rebuild(
    document_id: str,
    owner_user_id: str,
) -> RebuildPreparation:
    """
    校验重建条件并创建 rebuild task，但不在当前请求线程执行导入图。

    API 拿到返回值后再注册 persistent task，并交给 BackgroundTasks 调用
    已有 invoke_graph。这样 service 不依赖 FastAPI。
    """
    repo = get_import_metadata_repository()
    document = repo.get_document(document_id, owner_user_id)
    if not document:
        raise DocumentNotFoundError(f"document_id={document_id} 不存在")
    if document.get("status") == STATUS_DELETED:
        raise DocumentStateError(f"document_id={document_id} 已删除，不能重建索引")
    if document.get("status") not in {STATUS_COMPLETED, STATUS_FAILED}:
        raise DocumentStateError(
            f"document_id={document_id} 当前正在处理，不能重建索引"
        )

    source_file_path = Path(document.get("file_path", ""))
    if not source_file_path.is_file():
        # 必须先检查文件，再创建 task 和递增 index_version。
        # 否则一个必然无法执行的请求也会污染 document/task 状态。
        raise DocumentStateError(
            f"document_id={document_id} 的原始文件不存在，无法重建索引"
        )

    task_id = str(uuid.uuid4())
    local_dir = (
        PROJECT_ROOT
        / "output"
        / datetime.now().strftime("%Y%m%d")
        / task_id
    )
    local_dir.mkdir(parents=True, exist_ok=True)

    updated_document, _task = repo.create_rebuild_task_metadata(
        document_id=document_id,
        task_id=task_id,
        owner_user_id=owner_user_id,
        local_dir=str(local_dir),
    )

    return RebuildPreparation(
        task_id=task_id,
        document_id=document_id,
        dataset_id=updated_document["dataset_id"],
        owner_user_id=owner_user_id,
        tenant_id=updated_document.get("tenant_id", DEFAULT_TENANT_ID),
        visibility=updated_document.get("visibility", DEFAULT_VISIBILITY),
        index_version=int(updated_document["index_version"]),
        source_file_path=source_file_path,
        local_dir=local_dir,
    )
```

```python
    register_persistent_task(
        task_id,
        preparation["document_id"],
        preparation["dataset_id"],
        preparation["owner_user_id"],
    )
    background_tasks.add_task(
        invoke_graph,
        task_id=task_id,
        dataset_id=preparation["dataset_id"],
        document_id=preparation["document_id"],
        index_version=preparation["index_version"],
        owner_user_id=preparation["owner_user_id"],
        tenant_id=preparation["tenant_id"],
        visibility=preparation["visibility"],
        local_file_path_obj=preparation["source_file_path"],
        local_dir_path_obj=preparation["local_dir"],
    )

    return RebuildDocumentSchema(
        message="重建索引任务已创建",
        task_id=task_id,
        document_id=preparation["document_id"],
        dataset_id=preparation["dataset_id"],
        index_version=preparation["index_version"],
    )
```

注意：重建 API 不调用 `add_running_task(task_id, "upload_file")`，因为它没有重新上传文件。后台执行开始后，`invoke_graph` 和各节点会正常写 processing/running 状态。

## 十、容易写错的地方

### 10.1 不要按 subject_id 删除三张 Milvus collection

单个 document 删除时只删除它自己的 chunk。一个 subject 可能关联多个 document，删除标准主题或全部别名会影响其他文档。

### 10.2 不要按 file_title 删除

文件名只负责展示。同名文件可能属于不同用户、不同 document。

### 10.3 原文件检查必须早于创建 rebuild task

如果先递增 index_version、再发现文件不存在，Mongo 会留下一个永远无法执行的重建任务。

### 10.4 MinIO 前缀必须补 `/`

`prefix="kb-images/doc_1"` 可能同时匹配 `doc_10`。应使用 `kb-images/doc_1/`。

### 10.5 重建不能重置 owner/tenant/visibility

重建是原 document 的新索引版本，不是新 document。权限字段必须沿用原记录。

### 10.6 不要在 service 中抛 HTTPException

service 只抛业务异常，API 再映射为 404、409 或 500。这样 service 可以独立测试，也不会绑定 FastAPI。

### 10.7 明确先删后插的失败语义

重建进入 Milvus 节点后，会先删除旧 chunk，再插入新 chunk。如果插入失败，旧 chunk 不恢复，document/task 标记 failed，避免继续召回过期内容。

### 10.8 不要操作仍在导入中的 document

删除或重建 uploaded/processing document 会与旧后台任务竞争。当前阶段不引入分布式锁，最小可靠规则是：只允许对 completed/failed document 删除或重建，其余状态返回 409。

这层 service 校验能覆盖正常请求，但不是严格的并发锁。如果未来存在多个服务实例和高并发重复重建，应把状态检查与状态迁移收敛为 Mongo 原子 `find_one_and_update`。

## 十一、完成标准

代码完成后，应能明确验证：

- `DELETE /documents/{document_id}` 只能删除当前用户自己的 document。
- 删除成功后 Milvus 不再存在该 document 的 chunk。
- 删除成功后 MinIO 不再存在该 document 图片前缀下的对象。
- Mongo document 仍存在，但 `status=deleted` 且 `deleted_at` 非空。
- 默认文档列表隐藏 deleted，显式 `status=deleted` 可以查看删除历史。
- `POST /documents/{document_id}/rebuild` 保持 document_id 不变。
- rebuild task_id 是新值，`task_type=rebuild_index`，`index_version` 递增。
- 原文件不存在、document 已删除或 owner 不匹配时不会创建重建任务。
- uploaded/processing document 删除或重建时返回冲突，不与旧后台任务并发执行。
- 重建最终复用已有导入图，并由第四部分的 `document_id` 幂等逻辑替换 chunk。
- 全量测试通过。
