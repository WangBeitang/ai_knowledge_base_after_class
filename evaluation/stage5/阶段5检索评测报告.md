# 阶段 5 检索评测报告

## 当前状态

评测运行器和三种召回模式已经实现，但本报告暂不填写 A/B/C 结论。原因是当前 Milvus
测试 collection 将由项目维护者删除并按阶段 5A schema 重新导入，旧 chunk ID 不能作为
新评测标注。没有固定数据快照和真实 `expected_chunk_ids` 时，任何 schema 胜负结论都是
不可复现的。

## 运行前准备

1. 删除旧 chunk collection，使用阶段 5A 三路 schema 重建。
2. 重新导入同一批公共/private/shared 测试文档。
3. 复制 `retrieval_cases.template.jsonl` 为 `retrieval_cases.jsonl`。
4. 使用重新导入后的真实 `subject_id/chunk_id` 标注 24～40 条病例。
5. 固定 collection 数据、权限范围、chunk、reranker 和当前检索配置版本。

## 运行命令

```bash
uv run python evaluation/stage5/run_retrieval_eval.py \
  --cases evaluation/stage5/retrieval_cases.jsonl \
  --output evaluation/stage5/retrieval_eval_results.json
```

正式报告禁止使用 `--allow-small-set`。该参数只用于开发阶段验证脚本能运行。

## 冻结后的决策门

- 至少两个核心质量指标稳定、实质提升，且其他核心指标没有明显回退，才保留新增通道。
- 报警码、设备型号、SOP/零件编号子集的 Recall 不能为平均指标让路。
- 质量接近时选择字段更少、入库更快、依赖更少的组合。
- 三路只有相对最佳双路仍有稳定增益时才保留。

## 最终结论

当前：**待真实评测，不能选择 A/B/C。**

- A：保留 dense + learned sparse，删除 BM25。
- B：保留 dense + BM25，删除 learned sparse。
- C：保留 dense + learned sparse + BM25。
