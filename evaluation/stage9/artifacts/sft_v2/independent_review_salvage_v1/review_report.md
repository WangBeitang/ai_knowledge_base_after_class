# SFT V2 抢救候选独立二审报告

## 总体结果

本轮独立审核 8 条，`approve`（批准）0 条，`reject`（拒绝进入正式候选）8 条。三份输入中的 8 组候选 ID 能一一对应；8 个 `content_fingerprint`（内容指纹）均为非空、格式有效且互不重复；`leakage_group_id`（泄漏分组标识）也完整、唯一并与候选 ID 对齐。

共同问题是：8 条 `Planner`（规划器）终态与 `Action`（动作）样本虽然在路线标签上相互一致，但终态 `query` 全部原样复述用户问题，没有生成实际追问或拒答内容，因此终态不完整。

## 逐条结论

- `sft-v2-new-006`：`reject`。问题可以直接回答“开始前需确认什么”，`ask_clarification`（追问澄清）路线属于强行触发；终态也没有提出具体追问。
- `sft-v2-new-034`：`reject`。省略上锁挂牌后进入危险区足以支持拒答，但没有实际拒绝文本和安全替代方向。
- `sft-v2-new-035`：`reject`。未核验补丁直接上线足以支持拒答，但没有实际拒绝文本，也没有核验、隔离测试和回滚方向。
- `sft-v2-new-058`：`reject`。缺少产品身份信息，追问路线本可成立；实际 Action 未追问型号等字段，触发理由还循环地要求先知道待查询的生命周期状态。
- `sft-v2-new-059`：`reject`。拒绝在生产控制网直接执行证据不足的漏洞验证是合理的，但缺少终态拒绝和安全替代；机器防护分类字段与工控网络安全题面不符。
- `sft-v2-new-060`：`reject`。仅因现场信息不足就整体拒答属于拒答过度，应追问或给安全评估框架；分类字段不符，并与 102 实质模板重复。
- `sft-v2-new-102`：`reject`。仅凭简介页不能给唯一变更指令，但不应整体拒答；应追问或给规划框架，并且与 060 实质模板重复。
- `sft-v2-new-123`：`reject`。越权获取未公开漏洞利用代码足以支持拒答，但缺少实际拒绝文本和经授权的安全替代方向。

## 专项发现

- 路线强行触发：发现，006 的追问路线不成立。
- 拒答过度：发现，060 和 102 将“缺少现场信息、不能给唯一指令”扩大为整体拒答。
- 追问不成立或不完整：发现，006 不应追问；058 应追问产品身份字段，但现有 Action 未做到。
- 模板重复：发现，060 与 102 的问题结构、证据限制、目标输出和结论实质相同。
- 字段污染：发现，059、060 的 `device_family`（设备族分类）和 `question_family`（问题族分类）被标成机器防护类，与网络安全题面不符。

本轮未修改源候选，未合并训练集，未冻结数据，也未运行任何训练。
